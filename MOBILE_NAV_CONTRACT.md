# Mobile workspace wire contract v1

Additive to `apps/purepoint-mobile/docs/contract.md`. All requests use existing authenticated WSS envelope `{version:1,id,clientId,op,...}` and receipt `{type:"receipt",id,ok:true,data}` or `{type:"receipt",id,ok:false,error:<string>}`. Request id remains transport correlation; `operationId` below is durable-form identity. No Pi readiness dependency.

Permissions discovery (`permissions` result and `permissions` event): `{terminals:"off"|"view"|"control",workspaceManagement:false,workspace:{version:1,inventory:true,management:true,operationStatus:true}}`. Missing workspace means unsupported; missing grant means false. All mutations require terminals control AND workspaceManagement true; all fleet reads require terminals view/control. Local owner admin `devices.workspaceManagement {deviceId,workspaceManagement:<boolean>}`. Existing grants default false. Permission loss fences dispatch and late responses; cancellation cannot roll back committed work.

`agents` retains machines and agent fields, adds each machine `metadataStatus:"complete"|"partial"|"offline"`, `metadataError:string|null`, `projects:[{id:<exact registered project root>,name,available,error,counts:<daemon counts>}]`, `worktrees:[{projectId,id,name,path,branch,status,agentIds:[string]}]`. Agent projectRoot is project ID; worktreeId null means root only when project metadata confirms association. Machine id scopes every project/worktree/agent. Off returns no metadata (request denied). Projects and worktrees queried separately; unsupported metadata produces partial with usable agents. No projects inferred from agents. Machine offline differs from incomplete metadata. Queries bounded to 32 machines, 4096 entries per kind, 5s each, four machines concurrently.

`workspace.catalog {machine,projectId}` returns `{agents:[{id,name,available:boolean}],presets:[{id,name,agentType,prompt}],terminalAvailable:boolean,complete:boolean}`. IDs are canonical daemon configuration keys, never display labels. Availability means executable resolvable by daemon (not guarantee launch succeeds). No executable/args/env/config exposed. Presets are safe prompt-only definitions with supported available agentType; arbitrary command presets excluded. Unsupported catalog fails explicitly; forms gated. Catalog revalidated at launch.

Management fields are strict allowlists. Common `{operationId:<8..128 ASCII alnum underscore hyphen>,machine,projectId}`. Unknown fields rejected except envelope fields. IDs/targets are resolved from fresh authoritative inventory; client cwd/command/env/args/IPC rejected. Operation ID scoped to authenticated device and bridge instance, across socket reconnects. Client generates once before sending and persists submitted form; never generates replacement automatically.

- `workspace.spawn`: common + `{target:"root"|"worktree"|"newWorktree",worktreeId?:string,name?:string,base?:string,agentType:string,presetId?:string,prompt:string,planMode?:boolean}`. Existing requires exact worktreeId. Root forbids worktreeId/base. New requires name, permits base, forbids worktreeId. Prompt 1..65536 UTF8 bytes (preset prompt prepended server-side); name 1..80, base 1..128 conservative git-ref characters. planMode defaults false. Result mutation detail `{agentId,worktreeId:string|null}`.
- `workspace.createWorktree`: common + `{name,base?:string}`. Result detail `{worktreeId}`.
- `workspace.terminal`: common + `{target:"root"|"worktree",worktreeId?:string}`. Uses scoped Spawn terminal without command, ensuring manifest association. Result detail `{agentId,worktreeId:string|null}`.
- `workspace.rename`: common + `{agentId,name}`. Membership must match exact project. Result detail `{agentId}`.
- `workspace.stop`: common + `{agentId,confirm:true}`. Only Kill Agent target. Result detail `{agentId}`.

Mutation result `{operationId,state:"succeeded"|"failed"|"uncertain",detail?:<above>,message?:string}`. `workspace.operation {operationId}` is read-authorized and returns `{operationId,state:"pending"|"succeeded"|"failed"|"uncertain"|"unknown",detail?,message?}`. No mutation events beyond existing permissions; clients explicitly refresh status and agents. Errors before dispatch are failed; errors after dispatch conservatively uncertain (even daemon errors can follow a committed spawn). Duplicate pending ID rejected; identical completed ID returns ledger status without dispatch; different payload same ID rejected. Ledger retains max 2048 operations for bridge process lifetime, does not evict pending; full ledger rejects new mutations. Restart loses ledger: unknown NEVER means safe to retry. Inventory refresh may locate committed work but absent inventory is not proof of non-commit. User must review authoritative inventory before explicitly initiating any new operation. No automatic replay/retry on reconnect or timeout. A committed-but-unacknowledged operation stays uncertain; no rollback claimed.

Errors use existing receipt error strings with stable prefixes `workspace_permission`, `workspace_invalid`, `workspace_target`, `workspace_unsupported`, `workspace_duplicate`, `workspace_capacity`. Status requires current read grant and only reveals caller's operations. Downgrade suppresses detail; revoke closes connection. Legacy clients ignore additive fields. Names reject control characters; machine/agent/worktree IDs max128. No bulk target, removal, arbitrary path, shell command, config or SSH APIs.
