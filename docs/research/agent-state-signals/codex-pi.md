# Codex CLI and pi state signals

## Codex: what is verified and what can be installed?

### Takeaway
Current official documentation and source confirm the new lifecycle hooks; the old completion-only `notify` limitation is no longer the complete picture. Hooks still cannot by themselves provide an authoritative all-five-state view: Stop occurs before other hooks can request continuation, PermissionRequest occurs before approval may be auto-resolved, and no question/error lifecycle hook is listed. Prefer an app-server integration where PurePoint owns the session; treat CLI hooks as a degraded bridge.

### Cited Findings
- Inspected installed CLI `codex-cli 0.163.0`; pinned upstream source main SHA `5009a99dfc07830ddf7464c26f310a2b8532b55d` (2026-10-16). Source main is not asserted identical to installed binary. Official documentation was reachable: [Hooks](https://developers.openai.com/codex/hooks) redirects to [current hooks page](https://learn.chatgpt.com/docs/hooks). Documentation is unversioned; observations below separate binary from source.
- Official supported lifecycle names are `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SessionStart`, `SessionEnd`, `SubagentStart`, `SubagentStop`, `UserPromptSubmit`, `Stop`, `Interrupt`. No `StopFailure`, question, or generic error lifecycle hook is listed. [Docs](https://learn.chatgpt.com/docs/hooks); [pinned enum](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/hooks/src/schema.rs).
- FINISHED: `Stop` includes `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`, `permission_mode`, `turn_id`, `stop_hook_active`, `last_assistant_message`. It is a deterministic **stop attempt**, not final idle: a concurrent Stop hook may return `decision:block` and a reason to continue. Source runs Stop only on normal no-follow-up path; error exits can bypass it. [Docs](https://learn.chatgpt.com/docs/hooks#stop); [turn loop lines around 720](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/core/src/session/turn.rs).
- NEEDS PERMISSION: `PermissionRequest` adds `tool_name`, `tool_input` (possibly `.description`) and turn ID to common fields, before normal approval workflow. Another hook may allow/deny without displaying a prompt; deterministic pending authorization intent, not proof of user blocked. Permission hooks can approve or deny. No permission-replied lifecycle hook is documented. [Docs](https://learn.chatgpt.com/docs/hooks#permissionrequest).
- WORKING: `UserPromptSubmit` with `prompt` and `turn_id` deterministically reports submitted prompt before it proceeds, but another hook can block prompt. `PreToolUse` reports tool attempt, not entire thinking interval. [Docs](https://learn.chatgpt.com/docs/hooks#userpromptsubmit).
- INTERRUPTED: `Interrupt` explicitly fires only for active main-thread interruption, not idle/subagent. Default timeout 1 second, configurable 1–3 seconds; cannot prevent interruption/restart. [Docs](https://learn.chatgpt.com/docs/hooks#interrupt).
- ASKING QUESTION: `request_user_input` exists and source allocates oneshot pending-response channel, emits `RequestUserInput`, then awaits response. It is not in hooks schema. Source supports `is_blocking` / app-server `isBlocking`; use this field instead of assuming all user input requests block. [request implementation](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/core/src/session/mod.rs#L3236); [wire params](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/app-server-protocol/schema/typescript/v2/ToolRequestUserInputParams.ts).
- App-server exposes `turn/started`, `turn/completed`, `item/tool/requestUserInput`, `mcpServer/elicitation/request`, `item/commandExecution/requestApproval`, `item/fileChange/requestApproval`, `item/permissions/requestApproval`, and `serverRequest/resolved`. Turn object `status` is `completed | interrupted | failed | inProgress`, plus nullable `error`. These give deterministic working, terminal outcome and specific unresolved server requests **when PurePoint is the owning protocol client**. This does not imply a separate app-server can subscribe to an arbitrary existing TUI process. [Server requests](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/app-server-protocol/schema/typescript/ServerRequest.ts); [notifications](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/app-server-protocol/schema/typescript/ServerNotification.ts); [Turn](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/app-server-protocol/schema/typescript/v2/Turn.ts).
- Legacy `notify` serializes only `agent-turn-complete`; argv final JSON contains kebab-case `thread-id`, `turn-id`, `cwd`, optional `client`, `input-messages`, `last-assistant-message`. It spawns child and does not await exit; spawn failure is FailedContinue. No approval notification variant exists there. [source](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/hooks/src/legacy_notify.rs).
- Command hooks receive JSON via stdin and default to synchronous 600-second timeout. `async:true` runs background, cannot control operation, max eight concurrent per session, additional queued; canceled on session end; completion order can differ. `SessionEnd` always synchronous. Notification adapter should explicitly use short timeout, no stdout/stderr output, exit zero, and a bounded local write rather than network wait. [Docs](https://learn.chatgpt.com/docs/hooks#run-hooks-in-the-background).
- Hooks discover `hooks.json` alongside active config layers or inline config.toml hooks, user `~/.codex` and project `.codex`; definitions merge across layers. Non-managed hook content hashes require review/trust; changed hooks skipped until trusted. Project hooks require project trust. [Docs](https://learn.chatgpt.com/docs/hooks#where-codex-looks-for-hooks).
- Subagent hook common `session_id` uses parent session; SubagentStart/Stop add `agent_id`, `agent_type`, `agent_transcript_path`. Internal/synthetic subagents can suppress user-configured Stop/SubagentStop, so not every internal task is a separately observable child. [Docs](https://learn.chatgpt.com/docs/hooks#common-input-fields); [source](https://github.com/openai/codex/blob/5009a99dfc07830ddf7464c26f310a2b8532b55d/codex-rs/core/src/hook_runtime.rs).

### Inferences
- Minimum degraded CLI hook bridge: UserPromptSubmit, Stop, PermissionRequest, Interrupt, optionally SubagentStart/Stop; no config surface can promise all five states. Never parse a final `?` as deterministic asking-user signal. Prefer app-server for full state, with a human decision about changing the current TUI/PTY UX.
- Install a PurePoint-owned hooks file/config layer only if launch-time layer support is verified; otherwise merge one identifiable handler per needed event into project `.codex/hooks.json` with existing arrays preserved, backups/hash manifest, and explicit hook trust onboarding. Do not overwrite notify or user config. Uninstall only matching handler objects and owned scripts, retain unrelated hooks and any changed user files. Use launch environment agent UUID + worktree ID + launch nonce as authoritative identity; native session/turn fields enrich it. Do not use cwd alone.
- Awaited synchronous network calls can stall turns; async hooks avoid direct stall but need bounded local queue and sequence/reconciliation to tolerate ordering/loss. Permission observer must not emit decision fields, alter policy, or return malformed output.

### Gaps
- Runtime observed with fully isolated HOME/CODEX_HOME and throwaway cwd, no copied auth: `codex exec --json` emitted `{"type":"thread.started","thread_id":"01a14754-7b35-7e83-9a45-a87958581bc3"}`, `{"type":"turn.started"}`, repeated nonterminal `error` reconnect records, then `{"type":"turn.failed","error":{"message":"unexpected status 401 Unauthorized: Missing bearer or basic authentication in header, ..."}}`, process exit 1. Confirms retryable error != turn failed. Does not test hooks or authenticated completion/approval/questions/interrupt.
- Need pinned release compatibility tests: authenticated normal completion, other Stop hook continuing, auto-allow PermissionRequest, manual allow/deny, blocking/nonblocking question, final provider error after retries, Ctrl-C, subagent Stop/root distinction, listener down and hook timeout. No missing-auth result is evidence of missing feature.
- App-server source proves exposed schemas but this investigation did not launch full app-server lifecycle with model credentials. Official docs are current/unversioned, no first supporting release established; pin and capability-probe rather than claiming all historical Codex versions supported.

## pi: what signals actually exist now?

### Takeaway
Current pi 1.3.0 includes both final `agent_settled` and explicit `ui_prompt_start`/`ui_prompt_end` extension events. This directly supersedes the premise that no waiting-user event exists. UI wait is deterministic, but generic confirmation does not reveal whether its semantic purpose is permission or a question.

### Cited Findings
- Repository `badlogic/pi-mono` currently leads to source identity `earendil-works/pi`; pinned SHA `8efd314fa3d3232ce197d8d7a6a5660530b9d83e`; package `@earendil-works/pi-coding-agent` 1.3.0. `npm view` confirmed published 1.3.0; legacy `@mariozechner/pi-coding-agent` latest observed 0.73.1. Do not silently apply 1.3.0 claims to the legacy package. [package source](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/package.json).
- FINISHED: `agent_settled` payload `{type:"agent_settled",aborted:boolean}` fires after no automatic retry, compaction recovery, or queued continuation remains. `agent_end` merely ends one low-level run; not final. [extension docs](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/extensions.md); [JSON lifecycle](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/json.md).
- WORKING: `agent_start` `{type:"agent_start"}`; run is already busy during startup/compaction check and before_agent_start, so use before_agent_start if representing the entire startup interval. [docs](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/extensions.md).
- ASKING QUESTION: `ui_prompt_start` / `ui_prompt_end`, `{type,reason:"ui_prompt",kind:"select"|"confirm"|"input"|"editor"|"custom",title?:string}`. Runner wraps UI methods, counts nesting and emits outer start plus final end in finally, asynchronously via queueMicrotask. Exact method events are deterministic for wrapped ctx.ui; arbitrary external dialogs and plain prose questions are not covered. [types](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/src/core/extensions/types.ts#L1040); [implementation](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/src/core/extensions/runner.ts#L574).
- `ctx.ui.confirm/select/input` genuinely return unresolved dialog promises in interactive and RPC modes; RPC emits `extension_ui_request` with unique `id`, method and inputs; client sends `extension_ui_response`. Optional timeout/abort can resolve default false/undefined. Calling a method without awaiting still displays UI but caller may run concurrently; event alone says dialog open, not necessarily all model work blocked. No-op UI context in print/no-UI mode is not wrapped. [RPC implementation](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L85); [runner](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/src/core/extensions/runner.ts#L570).
- NEEDS PERMISSION: no universal built-in policy approval lifecycle. Extensions can await confirm in `tool_call` then return `{block:true,reason:...}`. Generic confirm can mean anything; tool_call does not imply permission. An approval extension must add explicit semantic metadata/shared event, or PurePoint should label generic user input only. [docs example and error contracts](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/extensions.md).
- ERRORED: final outcome can be obtained from `agent_before_settle.outcome` (`completed|aborted|error`) paired with subsequent `agent_settled`; before-settle can request continuation so must not notify until settled. Also inspect final assistant message stopReason `error`; retries may replace errors before final settle. `agent_settled.aborted` distinguishes interruption. Tool execution error becomes tool result and is not fatal turn error. [types](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/src/core/extensions/types.ts#L973); [settlement implementation](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/src/core/agent-session.ts#L1980).
- Extensions run in-process, factories and most lifecycle handlers can be awaited; no blanket extension timeout is documented. Handler errors generally reported and continuation attempted, except failed tool_call handler blocks tool as fail-safe. Do not put network awaits or throws in observer tool_call. [docs](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/extensions.md).
- Extension installation supports `pi --extension /absolute/purepoint.ts` without touching user config, or project `.pi/extensions/` and user `~/.pi/agent/extensions/`. PI_CODING_AGENT_DIR redirects entire agent directory, including settings/auth/session data; use only testing, not a transparent production override. ctx.sessionManager supplies session identity. [configuration](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/configuration.md); [extensions](https://github.com/earendil-works/pi/blob/8efd314fa3d3232ce197d8d7a6a5660530b9d83e/packages/coding-agent/docs/extensions.md).

### Inferences
- Minimum adapter: single explicit `--extension` owned by PurePoint subscribing before_agent_start/agent_start, agent_before_settle, agent_settled, ui_prompt_start/end, session lifecycle; no tool interception needed for generic state. Use launch identity + sessionManager ID; no built-in subagent model was established, so extension-spawned other sessions need independent launch identity.
- Keep internal awaiting-user-input separate from generic permission reason. For unsupported old versions degrade to agent_end only as nonfinal progress, process supervision plus unknown state; do not synthesize certainty. Negotiated cooperative permission extension can refine UI confirm to permission.
- Install writes one PurePoint-owned extension under `.pu/...` and changes only launch argv. Uninstall removes argv flag and owned extension; no real ~/.pi change necessary. Any durable local event outbox belongs under `.pu`, not session transcript.

### Gaps
- Runtime observed: installed exactly @earendil-works/pi-coding-agent@1.3.0 under /tmp/pp-signal-sandbox/npm with isolated HOME and PI_CODING_AGENT_DIR. A temporary explicit extension registered `/probe` calling awaited ctx.ui.confirm/select/input; RPC harness answered each UI request. Observed all three extension_ui_request objects and all six ui_prompt_start/end events, e.g. `{"type":"ui_prompt_start","reason":"ui_prompt","kind":"confirm","title":"Probe confirm"}` then matching end; select and input equivalent. `/probe` completed with `{"id":"probe","type":"response","command":"prompt","success":true,"data":{"disposition":"handled"}}`, correctly no agent_start/settled because command handled without model turn. This verifies dialogs without API credentials, not LLM lifecycle.
- No authenticated normal model completion, model-origin tool permission, provider error, or run interruption was executed. Builder should use mock provider fixtures (or authorized test credentials), force retry/recovery then settle, queued follow-up, before-settle continuation, and listener outage. Also test nested UI, nonawaited UI, print no-UI, abort timeout, and legacy 0.73.1 package separately.
- Reproduction artifacts remain only in /tmp/pp-signal-sandbox (probe.ts/probe.py/pi-events.jsonl); source clones /tmp/pp-signal-codex and /tmp/pp-signal-pi. No real CLI config modified; no PurePoint implementation changes.
