# Native signals make agent attention trustworthy

Discovery and builder plan, 2026-10-16. **Planning only: no adapter implementation, production configuration changes, commit, push, spec advancement, or app build is authorized by this document.** PurePoint baseline: `c6a4cde9f17051cc05fc745140571561e7767642`, branch `pu/not`. This report is a research artifact outside `docs/`, not an adopted product specification.

**Use native structured events, preserve their limits, and keep process liveness separate from turn state.** Claude Code and OpenCode are the first integration candidates; current Codex and pi expose more than the original premise suggested. Codex has real lifecycle hooks and pi has explicit UI prompt events. Gemini offers useful permission and question signals; Cursor offers limited PTY hooks and a stronger, architecturally different ACP mode. No investigation here established all five live scenarios for all six tools. “Deterministic” below means the exact fact stated in a row, not successful task completion or proof that every concurrent agent activity stopped. Source-confirmed capabilities must pass release-qualified sandbox tests before production activation.

## 1. Verified event matrix and payload contracts

Ratings: **D** = deterministic native fact within stated scope; **H** = heuristic interpretation; **U** = unavailable through that adapter; **V** = runtime qualification still needed. A deterministic stop *attempt* is not deterministic final idle when another hook can request continuation. Blocking describes native dispatch, not our proposed transport. Error means terminal turn failure; an individual failed tool or retryable provider error does not establish it. Interrupt is a separate outcome and never automatically an error.

V1 envelope `{type,properties}` differs from v2 `{id,type,created,data,location?,metadata?,durable?:{aggregateID,seq,version}}`. V2 lifecycle events are durable, permission/forms ephemeral; replay lifecycle and re-query pending attention after reconnect. V2 `session.execution.interrupted` carries `{sessionID,reason:"user"|"shutdown"|"superseded"|"inactivity"}`; shutdown preserves claim for continuity. V1 cancellation sets idle, so idle alone cannot distinguish interruption. V1 typed plugin key `permission.ask` is **not a bus event**; no runtime `Plugin.trigger("permission.ask",...)` callsite was found. Observe `permission.asked` instead. ## 3. Architecture: separate observation, activity, attention and outcome

Current code deliberately exposes only process liveness: `AgentStatus::Running|Broken` in [agent.rs](../../../crates/pu-core/src/types/agent.rs); [agent_monitor.rs](../../../crates/pu-engine/src/agent_monitor.rs) returns Broken for **any** process exit, including zero. Legacy idle/waiting deserialize to Running. [AgentStatusReport](../../../crates/pu-core/src/protocol/payloads.rs) carries process/identity and `idle_seconds`; terminal silence is not model idle. Retain this contract and add an independent optional activity object. [agent-lifecycle.md](../../product/agent-lifecycle.md) AL-001 still describes 30-second/shell-prompt Waiting detection, contrary to current source; reconcile it through spec review before implementation. Do not revive terminal scraping as authoritative state.

Proposed model: `activity=unknown|working|idle`, `attention` as a set of `{request_id,kind:permission|question|decision|unknown,blocking:known_true|known_false|unknown,source_session}`, `last_outcome=completed|errored|interrupted|unknown`, `observation=connected|disconnected|unsupported`, and evidence metadata `{native_event,adapter_version,confidence,observed_at,source_sequence}`. UI derives the requested labels from these independent facts. A live unanswered attention request can coexist with working. Failed terminal turn remains Errored until next confirmed start; interrupted remains distinct. Unknown/disconnected must be visible rather than retaining an apparently current Working or inventing Finished. Quiet output, elapsed time, final punctuation, tool failure and child completion never prove root completion.

Proposed normalization envelope: `{schema_version,agent_id,worktree_id,launch_generation,tool,tool_version,native_session_id,parent_session_id?,turn_id?,request_id?,event_id?,source_sequence?,observed_at,kind,evidence}`. Existing lifecycle code injects `PU_AGENT_ID`, `PU_PROJECT_ROOT`; extend it with immutable launch generation and per-launch capability. Register native sessions under this launch, validate manifest ownership, and use cwd only as diagnostic context. A child inheriting the root token still needs explicit child identity/ancestry; never accept its terminal event as root terminal state. Claude SubagentStart/Stop and tool agent IDs, Codex parent session plus agent_id, OpenCode parent session queries, pi sessionManager identity and Cursor ACP task IDs require adapter-specific handling. Gemini lacks verified parent ID in common hook fields; unresolved ancestry cannot assert root terminal state. Pi extension-created sessions require independent binding; no universal built-in subagent mapping was established. Global OpenCode forms require a separately proven owner or project-level attention.

Recommended transport is a **launch-scoped local relay**, never push delivery inside a hook. An owned small helper consumes bounded stdin, strips prompt/tool bodies by default, and submits a bounded message to a permission-restricted local Unix socket; inherit a capability through private launch material without logging it. Proposed engineering budgets, not measured guarantees: input cap 256 KiB, enqueue deadline 50 ms, absolute helper deadline 100 ms, empty stdout and exit0 for observer failures, capped per-launch outbox 1 MiB with explicit overflow/loss counter. Verify these values under load and adjust from measurements. Hooks must emit no policy decisions and never auto-answer user input. Avoid shell background grandchildren retaining hook pipes. A dead daemon or full queue can drop telemetry; the helper must attempt a persistent bounded loss/overflow marker outside the event queue, consumed on the next successful connection. Marker writes must obey the same deadline and can themselves fail. A receiver freshness watchdog independently expires stale observation; after daemon restart, observation starts unknown until reconciliation. A dropped one-shot hook has no guaranteed later event or guaranteed immediate detection: a marker requires a later connection, and freshness expiration indicates uncertainty rather than reconstructing the lost state. Neither event nor marker delivery may stall agent work. An async hook still needs helper bounds because async timeout behavior differs by tool.

Daemon receiver validates peer/launch capability, schema, generation and native binding; stale/replayed events cannot revive old sessions. Deduplicate by native durable ID/sequence when present; locally generated sequence is not an upstream causal ordering guarantee. Pending IDs are sets, removed only by matching resolution; unknown cancellation requires reconciliation, not clearing every request. Durable OpenCode lifecycle replay and authoritative pending snapshots recover after SSE loss; when a tool lacks snapshots mark observation unknown until fresh evidence. Hook-only stop candidates remain lower confidence, with any notification delay described as policy rather than proof. Out-of-process OpenCode stream, Codex app-server and Cursor ACP are preferred only when PurePoint owns their sessions. Protocol clients route actual questions/permissions to UI and must handle response deadlines/cancel, while telemetry remains independent.

Push policy consumes state transitions after reduction. Use idempotency `{launch,turn-or-request,outcome}` and suppress duplicate attention/completion pushes; state is updated even when app/agent is focused. Never tie focus gating to state correctness. Human selection of cooldown, foreground suppression and child-attention bubbling belongs in product decisions. Notification delivery failure does not change agent state or block the event receiver.
